# 03 — Logical Data Model

Implement SQLAlchemy tables with UUID PKs, `created_at`, `updated_at` (timezone-aware UTC), foreign keys, not-null constraints where indicated, useful indexes and Alembic migrations. Exact internal names may be adjusted if API tests and documentation remain consistent.

## Academic structure

| Entity | Key fields and rules |
|---|---|
| `institutions` | id, name, country fixed `MY`; avoid storing individual student information |
| `programmes` | id, institution_id, name, programme_code nullable, academic_year/version, active_revision_id nullable |
| `programme_revisions` | id, programme_id, version_label, effective_date nullable, created_at; preserve historical versions |
| `courses` | id, programme_revision_id, course_code nullable, course_name, course_type (`COMPULSORY|ELECTIVE|UNKNOWN`), credit_hours nullable, year/semester nullable, inventory_source_anchor_id nullable, extraction_status |
| `documents` | id, programme_revision_id, optional course_id, filename, format, content_sha256, parser_version, storage_path, content_status, is_synthetic, uploaded_at |
| `document_anchors` | id, document_id, page_number nullable (PDF 1-based), paragraph_index nullable (DOCX), section_label nullable, char_start nullable, char_end nullable, excerpt; stable referent to source |
| `learning_outcomes` | id, course_id, ordinal, original_text, source_anchor_id; never autogenerated as factual without source |
| `course_topics` | id, course_id, text, source_anchor_id |
| `course_assessments` | id, course_id, description, assessment_type nullable, source_anchor_id |

| `evidence_sources` | id, title, publisher, url nullable, source_kind, published_at nullable, observed_start nullable, observed_end nullable, retrieved_at, jurisdiction, licensing_note nullable, `is_synthetic`, checksum/version; distinguish publication date from observed period |
| `evidence_passages` | id, evidence_source_id, locator/page/section, exact_excerpt, claim_type (`AI_CAPABILITY|OCCUPATIONAL_TASK|SKILL_REQUIREMENT|EMPLOYMENT_INDICATOR|ACADEMIC_GUIDELINE|SDG`), skill_id nullable, occupation_id nullable, confidence_note nullable |
| `signal_snapshots` | id, name, captured_at, coverage_start/end nullable, metadata_json, is_synthetic; snapshot join table for evidence sources/passages |

|---|---|

## Integrity invariants

1. A programme contains many courses; an analysis run has **exactly one course analysis per identified course** (including insufficient evidence).
2. A source-linked finding has **valid local evidence references**; unknown IDs should fail validation.
3. A course with only its title (no detailed syllabus) cannot be assigned confirmed learning outcomes, verified skill depth, or definitive obsolete/retain conclusion.
4. Evidence sources must distinguish synthetic vs factual provenance; synthetic fixtures cannot masquerade as official data.
5. `INSUFFICIENT_EVIDENCE` is a **knowledge state**, NOT an implicit `KEEP_NO_CHANGE` recommendation.
6. Only one primary recommendation per affected target and analysis run unless documented as a programme-level combined action; alternatives remain accessible.
7. University humans approve/reject. AI recommendation creation never sets approval to `APPROVED`.
8. Foreign-key/cascade policies preserve historical reports, source revisions and approved decisions.

## Indexes

Prioritise `(programme_revision_id, course_code)`, `(analysis_run_id, course_id)` unique, `documents.content_sha256`, `(source_id, observed_start)`, `(analysis_run_id, is_primary)` and job status. Track identifiers and migration naming consistently.
