# Scenarios, SDGs and reporting

## Scenarios

Support **moderate** and **accelerated AI adoption**, grounded in explicit assumptions about change to tasks and evidence availability; these are comparative models, **not numerical predictions of jobs or placements**. Inputs and evidence snapshots are versioned; explain why an action changes between scenarios.

Demonstration: snapshot A -> analysis v1 -> snapshot B -> analysis v2; show a traceable changed signal and the exact impacted course or intervention. If an unrelated signal changes, results for unrelated disciplines should stay unchanged.

## SDG mapping

Meaningful explanatory links only. Likely starting points: SDG 4 (quality education), SDG 8 (decent work); connect more goals only when substantiated for specific occupation, skills or programme. Store target/goal, rationale, and original sources. Do not blindly label all roles as SDG 4 and SDG 8 without explaining relevance.

## Reporting

Academic proposal includes institution, programme, catalogue coverage, title-only warnings, workforce/AI sources with **dates**, reviewed course flags, proposed action vs alternatives/no change, evidence inspector, scenarios, implementation assumptions, human approval status, and explicit next data needed. Draft report != authorised curriculum change.

No need for full PDF generation in initial backend-only phases; structured JSON and Markdown export may be sufficient for the hackathon. Ensure data can support eventual downloadable reports.
